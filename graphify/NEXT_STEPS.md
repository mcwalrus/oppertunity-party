## Route B — pi.dev (llama.cpp local server as the LLM)

graphify v0.9.30 has **no native pi backend**. The pi-native path is pi's
llama.cpp router integration, which exposes an OpenAI-compatible endpoint that
graphify's `openai` backend can target.

```bash
# 1. In a pi session: /login llama.cpp   (default URL http://127.0.0.1:8080)
#    Manage/download models with /llama, or set up llama.cpp per pi docs
#    (docs/llama-cpp.md). Note the exact model name from:
curl http://127.0.0.1:8080/models

# 2. Point graphify at it (any non-empty API key works for local servers):
cd ~/.graphify/repos/Graphify-Labs/graphify
OPENAI_BASE_URL=http://127.0.0.1:8080/v1 \
OPENAI_API_KEY=local \
OPENAI_MODEL=<exact-model-name-from-/models> \
graphify . --backend openai
```

- Free, local, private. Quality depends on the GGUF model you load — prefer a
  coder-tuned model (e.g. a Qwen2.5-Coder GGUF).
- pi's role after the build is already wired up: the `graphify-pi` extension is
  installed in the oppertunity-party project, so pi will consult
  `graphify-out/GRAPH_REPORT.md` / `wiki/` automatically once they exist.
